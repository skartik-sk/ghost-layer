# ZIP 311 payment disclosure on testnet (2026-11-11)

A real [ZIP 311](https://zips.z.cash/zip-0311) disclosure, made for a real testnet payment and
checked against the chain. It uses the [`zip311`](../crates/zip311) crate (on crates.io), the
`zcash-devtool wallet disclose` patch ([patches/zcash-devtool](../patches/zcash-devtool)) and
`ghost proof verify`.

## 1. The payment (through Ghost Layer, over Nym)

`ghost pay`, from w1 to w2, 0.0005 TAZ, memo "ZIP 311 demo payment":

- broadcast after a 22.1 s random delay on fresh connection #5 via nym-broadcast
- txid `4d66c913f474717dcf2f7d5e54bb59f972a41e29099cf53b76d1eafddccecfc6`, mined at height **4608562**,
  218 s in total. Explorers: [zcashexplorer](https://testnet.zcashexplorer.app/transactions/4d66c913f474717dcf2f7d5e54bb59f972a41e29099cf53b76d1eafddccecfc6),
  [zexplorer](https://zexplorer.app/testnet/tx/4d66c913f474717dcf2f7d5e54bb59f972a41e29099cf53b76d1eafddccecfc6)

## 2. Create the disclosure (sender's wallet; the spending key never leaves it)

After syncing w1 through `ghost up` (Nym), this took 3 s:

```
$ zcash-devtool wallet -w w1 disclose -i w1.age --txid 4d66c913…cfc6 --msg "challenge: zip311-demo-2026-11-11"
Proving spend authority for 1 action(s), disclosing 1 output(s)...
zpd1…   (7,032 characters; the full string is below)
```

The recipient is w2's address (checked with `diff` against `w2.addr`).

## 4. Tampering, against the same mined transaction

`ghost --json proof verify --direct <changed string>`:

| changed | result |
|---|---|
| a byte of the signature | `invalid spend-authority signature for ironwood action 0` |
| a byte of the Halo2 proof | `invalid spend-authority proof for ironwood action 0` |
| a byte of the message | `invalid spend-authority signature for ironwood action 0` (the message is signed) |

This disclosure and the raw transaction are also an offline test vector:
`crates/zip311/tests/testnet_vector.rs` (`cargo test -p zip311 --release`).
